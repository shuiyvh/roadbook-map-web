# 智能路书后台全局 UI 重设计文档

生成日期：2026-07-08

## 1. 设计目标

当前前端基于若依后台模板，默认页面、组件间距、色彩、首页内容和部分交互仍带有通用管理系统痕迹。后续要接入路书地图工作台、推荐搜索、出行打卡、分享邀请和后台配置模块，如果继续按旧模板复制页面，会导致系统风格割裂、业务主次不清、页面维护成本上升。

本次重设计的目标是建立一套稳定的“智能路书工作台”后台视觉与交互规范，使现有页面可逐步迁移，后续新增页面也能直接套用统一结构。

## 2. 设计原则

1. 业务优先：页面首先服务路书规划、地图点位、出行进度、推荐结果和后台配置，不展示模板宣传、技术栈介绍、捐赠等无关内容。
2. 克制清晰：整体保持工具型产品风格，避免大面积装饰、营销式 hero、过度渐变和复杂背景。
3. 可复用：所有新增业务页面优先使用统一页面容器、筛选栏、表格、抽屉、弹窗、空状态和详情布局。
4. 低迁移风险：不一次性重写若依底层权限、路由、请求、菜单机制，先从视觉层和页面组织层逐步替换。
5. 可扩展：地图工作台、H5 出行页、后台配置页允许有不同信息密度，但共享色彩、字体、间距和组件状态。

## 3. 全局布局

后台主框架保留左侧导航、顶部工具栏、内容区结构，但需要重设信息层级。

1. 左侧导航：只展示业务模块，默认分组为“路书工作台、推荐与 AI、分享协作、出行管理、后台配置、日志审计、系统管理”。
2. 顶部工具栏：保留折叠菜单、面包屑、搜索、主题、全屏、消息、用户菜单；移除源码、文档、模板外链等入口。
3. 内容区：统一使用 `page-shell` 容器，页面宽度跟随后台内容区，不再嵌套多层卡片。
4. 首页：作为运营看板和模块入口，只展示与路书业务有关的数据概览、趋势图和待办状态。
5. 地图工作台：允许使用全屏式工作台布局，地图区域为主，点位列表、详情、推荐结果作为侧栏或抽屉。

## 4. 色彩规范

主色不继续沿用模板默认蓝色堆叠，采用“路线蓝 + 状态绿 + 风险橙 + 中性灰”的工具型配色。

1. 主色：`#2563EB`，用于主按钮、关键链接、选中态和主要趋势线。
2. 成功：`#16A34A`，用于已发布、已打卡、已启用。
3. 警告：`#F59E0B`，用于风险提醒、待处理、配置缺失。
4. 错误：`#DC2626`，用于删除、失败、禁用风险。
5. 背景：浅色模式 `#F6F7FB`，暗色模式 `#101418`。
6. 内容面板：浅色 `#FFFFFF`，暗色 `#171D23`。
7. 边框：浅色 `#E5E7EB`，暗色 `#27313A`。

禁止新增页面使用大面积紫色、蓝紫渐变、纯装饰色块或与业务无关的插画背景。

## 5. 字体与间距

1. 字体：沿用系统默认中文字体栈，不新增外部字体依赖。
2. 页面标题：24px 到 28px，列表页标题一般 20px 到 24px。
3. 区块标题：16px 到 18px。
4. 正文与表格：13px 到 14px。
5. 间距系统：8 / 16 / 24 / 32 px。
6. 卡片圆角：不超过 8px。
7. 表格和表单保持紧凑，但必须保证可读性，不做过度稀疏的营销页面布局。

## 6. 页面模板

### 6.1 列表页模板

适用于路书列表、推荐列表、分享列表、邀请列表、后台配置、日志列表。

结构：

1. 页面标题区：标题、简短说明、一个主要操作按钮。
2. 筛选区：常用条件最多首屏展示 4 到 6 个，更多条件折叠。
3. 表格区：统一表格密度、状态标签、操作列宽度。
4. 分页区：沿用现有分页组件。
5. 空状态：说明当前无数据原因，并给出下一步操作。

约束：

1. 一个页面只保留一个主要按钮。
2. 查询、重置、导出等次要动作使用弱化按钮。
3. 操作列按“查看、编辑、更多”收敛，删除类操作放入二次确认。

### 6.2 详情页模板

适用于路书详情、出行详情、审计日志详情、第三方调用日志详情。

结构：

1. 顶部摘要：名称、状态、更新时间、主要动作。
2. 主体信息：按业务分组展示，不堆叠长表单。
3. 时间线或明细表：展示点位、出行进度、调用记录。
4. 侧栏：展示风险提醒、权限、分享状态等辅助信息。

### 6.3 表单页模板

适用于新建路书、编辑路书、后台配置新增编辑。

结构：

1. 基础信息。
2. 业务配置。
3. 高级设置，默认折叠。
4. 底部固定操作栏：保存、取消。

约束：

1. 简单字段不额外封装组件。
2. 复杂字段要有中文说明和校验提示。
3. 敏感配置不明文展示完整密钥。

### 6.4 地图工作台模板

适用于 PC 路书地图工作台。

结构：

1. 顶部工具条：路书切换、保存状态、发布状态、导出入口。
2. 左侧点位列表：拖拽排序、每日分组、点位状态。
3. 中央地图：点位、分段路线、当前位置、风险标记。
4. 右侧上下文面板：点位详情、POI 搜索、推荐结果、评论。

约束：

1. 地图是主视图，不放进装饰卡片。
2. 列表、详情和推荐面板需要支持折叠。
3. 关键操作要有保存状态反馈，避免用户误以为已保存。

## 7. 组件规范

1. 状态标签：统一映射“草稿、已发布、已归档、进行中、已完成、已禁用、失败”。
2. 按钮：主按钮只用于当前页面最重要动作；危险按钮只用于删除、禁用、取消出行等高风险操作。
3. 表格：默认显示核心字段，长文本省略并支持悬浮查看。
4. 弹窗：只用于短流程确认和轻量编辑；复杂编辑使用抽屉或独立页面。
5. 抽屉：用于点位详情、推荐详情、日志详情等不应打断主流程的内容。
6. 空状态：必须说明原因和下一步，不允许空白区域。
7. 加载状态：接口请求超过短时间必须展示加载状态。
8. 错误状态：中文说明失败原因，保留重试入口。

## 8. 暗色模式

1. 新增页面必须支持现有暗色模式。
2. 不直接写死大面积白底或黑底，优先使用 CSS 变量。
3. ECharts 图表需要根据主题切换网格线、文字和 tooltip 背景。
4. 地图底图如无法暗色化，侧栏和控件仍需适配暗色模式。

## 9. 响应式要求

1. 后台管理页至少适配 1366px 及以上桌面屏。
2. 常规列表页在平板宽度下筛选区换行，表格允许横向滚动。
3. H5 出行页按移动端优先设计，不复用后台密集表格布局。
4. 地图工作台在窄屏下改为“地图 + 底部抽屉”结构。

## 10. 新增页面检查项

新增页面合并前必须检查：

1. 是否使用统一页面容器。
2. 是否只有一个主操作按钮。
3. 是否存在空状态、加载状态、错误状态。
4. 是否支持暗色模式。
5. 是否没有复制若依模板宣传、捐赠、技术栈、外链文案。
6. 是否没有把复杂业务塞进一个超长表单。
7. 是否对敏感信息做脱敏或避免展示。
8. 是否使用中文错误提示和操作反馈。

## 11. 落地顺序

1. 第一阶段：全局变量、布局基础、登录页、首页、顶部导航、侧边栏。
2. 第二阶段：列表页模板、表单页模板、详情页模板、空状态和加载状态组件。
3. 第三阶段：路书地图工作台页面框架。
4. 第四阶段：推荐、分享、邀请、出行、后台配置页面接入。
5. 第五阶段：暗色模式和响应式细节统一校正。

## 12. 与开发任务的关系

本设计文档是后续所有前端任务的最高优先级约束。业务功能开发前，应先确认目标页面套用哪类模板；如果现有模板不满足地图、出行或推荐等业务场景，应先扩展设计规范，再开发业务页面。
